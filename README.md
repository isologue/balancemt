# BalanceMT

一个面向多个 AI 中转站的轻量余额监控台。当前内置：

- `Sub2API`：`POST /api/v1/auth/login` + `GET /api/v1/auth/me`，读取 `data.balance`。
- `New-API`：`POST /api/user/login` + `GET /api/user/self`，读取 `data.quota`，按 `500000 quota = 1 USD` 换算。
平台下拉框仅提供 `New-API` 和 `Sub2API` 两种基础平台。添加、编辑时始终展示六项接口配置：登录路径、余额路径、账号字段、Token 字段、余额字段和余额除数。选择平台会填入对应默认值，切换平台会重置这六项参数，保留名称、地址、账号和凭据等其他信息。

任意接口参数偏离所选平台的默认值时，自动标记为“自定义兼容”，同时保留基础平台；手动改回全部默认值或点击“恢复默认接口”后，自动恢复为对应平台类型。编辑已有自定义站点时保留原接口参数，修改名称、密码、阈值等普通信息不会改变平台分类。余额除数支持正小数。

## Docker 部署

```powershell
Copy-Item .env.example .env
# 修改 .env 中的 ENCRYPTION_KEY
docker compose up -d --build
```

打开 `http://localhost:8080`，第一次访问会创建本地管理员账号。

构建默认使用官方 `golang:1.23-alpine` 镜像，服务器无需本机自定义的构建镜像；有离线镜像时可通过 `GO_BUILDER` 环境变量覆盖。

建议至少修改：

- `ENCRYPTION_KEY`：用于 AES-GCM 加密中转站密码，部署后不要随意改变，否则旧凭据无法解密。
- `MONITOR_INTERVAL_SECONDS`：后台自动检查间隔，默认 10 秒；旧的 `MONITOR_INTERVAL_MINUTES` 仍兼容，但建议改用秒配置。

SQLite 文件和余额历史保存在 `./data/balancemt.db`（容器内使用绝对路径 `/app/data`，并采用 DELETE journal，适配 Docker Desktop 的 Windows 挂载目录）。登录会话保存在数据库中，容器重启后仍会保持会话有效期内的状态。

## 告警配置

打开页面右上角的“告警配置”齿轮即可实时修改检查间隔、消耗统计窗口、邮件和短信告警，不需要改 `.env` 或重启容器。默认每 10 秒检查一次，间隔可配置为 1 到 86400 秒；消耗统计窗口默认近 24 小时，可配置为 1 到 720 小时；保存后立即唤醒监控计时器并使用新配置。

余额低于账户的“低余额提醒阈值”或检查进入失败状态时，会分别触发一次告警；恢复正常后会重置告警状态，避免每次检查重复发送。

页面支持以下通道：

- 邮件 SMTP：主机、端口、用户名、密码/授权码、发件人和一个或多个接收邮箱。
- Twilio 短信：`SMS_TO`、Account SID、Auth Token 和发件号码。
- 通用 Webhook：`SMS_TO`、Webhook URL 和可选 Token，请求体为 `{"to":"...","message":"..."}`。
- New-API 兼容：编辑站点时可填写 New-API 用户 ID；部分旧版或定制站点要求该值，程序会发送为 New-Api-User 请求头。

告警配置保存到 SQLite 的 `app_settings` 表中，密码和 Token 使用 `ENCRYPTION_KEY` 加密；首次启动时仍会从 `.env` 读取默认值。接口查询失败默认连续 5 次后才发送一次告警；成功查询会重置连续失败计数，同一轮连续失败不会重复发送。该次数可在页面告警配置中调整。弹窗内的“测试告警”会按当前表单配置发送测试消息，但不会自动保存，建议测试成功后再点“保存配置”。

`.env.example` 仍保留同名变量，适合首次部署或迁移旧配置；页面保存后的配置优先于环境变量。

## 当前边界

凭据加密、账号/历史记录、自动检查、低余额视觉提醒、邮件和短信告警已经具备；2FA 登录中转站、站点 Cookie 登录以及更复杂的 OAuth 暂未加入。对于打开了 Turnstile 或强制 2FA 的中转站，需要在目标站点关闭对应限制，或后续增加浏览器登录适配器。


## 配置导入与导出

页面右上角的 **⇅ 导入 / 导出** 可以把本地配置迁移到服务器：

1. 在本地选择“导出备份”，直接下载 `.balancemt.json` 文件，无需设置口令。
2. 在服务器部署并创建管理员账号，登录后打开“导入 / 导出”，选择“导入备份”。
3. 上传备份文件，选择重复站点处理方式，点击“开始导入”，无需填写口令。

备份包含全部站点的配置、账号密码、访问令牌、New-API 用户 ID、基础平台、自定义查询接口、换算参数、启用状态、提醒阈值，以及检查间隔、消耗统计窗口和完整邮件/短信告警配置。管理员账号、登录会话、余额采样和失败历史不包含在内；导入后按自动检查间隔重新获取余额。

默认跳过相同基础平台、站点地址（忽略末尾 `/`）和账号的重复站点；也可以选择使用备份覆盖。不会删除目标上其他站点。“同时导入告警配置和检查间隔”默认勾选，会完整替换目标上的告警设置并立即生效；取消勾选则保留目标配置。整份备份校验后通过 SQLite 事务一次性导入，失败不会留下部分配置。每份备份最多 1000 个站点，文件最大 8 MB。

备份使用 AES-256-GCM 加密（格式版本 3），每次导出生成随机 nonce。JSON 文件仅包含格式标识、算法、项目密钥标识、nonce 和密文，账号密码、令牌及告警配置均在密文内。程序在服务器端自动解密，无需设置或输入备份口令，文件被修改或损坏会拒绝导入。

备份密钥随当前项目的代码和构建镜像提供；本地与服务器使用同一项目构建即可互相导入，不需要使用相同的数据库 `ENCRYPTION_KEY`。请保留 `backup.go` 中的项目备份密钥，替换该密钥后将无法读取之前的备份。数据库中的凭据仍使用各部署独立的 `ENCRYPTION_KEY` 加密保存，导入时会自动重新加密。

这种自动解密用于避免直接打开备份暴露配置，不提供对持有项目源码或程序者的保密隔离；持有该项目的人可以恢复备份内容，因此仍应妥善保管文件。仅支持当前加密格式，请重新导出开发阶段生成的其他格式备份。


## 控制台实时显示

桌面端左侧依次显示总余额和当前账户详情，右侧显示账户列表。账户列表在窗口内独立滚动，默认按余额从低到高排列，支持切换为从高到低。多币种总余额分别展示；总余额卡片右上角纵向排列“添加站点”和“检查全部”按钮。账户列表和当前账户详情均展示统计窗口内的额度消耗及预计可用时间；历史数据不足时显示“数据积累中”，预计时间超过 24 小时会自动换算为天。

后台按配置的检查间隔查询中转站；打开的页面每 1～5 秒自动读取本地检查结果（默认 5 秒，检查间隔小于 5 秒时同步缩短）。页面同步不会额外触发中转站请求。切到后台标签时暂停页面读取，回到页面或网络恢复时立即同步；同步失败会显示重试状态，会话过期则返回登录页。编辑中的弹窗、选中的账户、排序和列表滚动位置会保留。需要主动发起检查时可用账户详情的单站检查或总余额卡片的“检查全部”。

“查看最近失败记录”展示最近 20 条失败项，点击记录展开完整报错，支持一键清空失败历史。数据库在启动时及新增失败记录时自动保留最新 20 条失败记录；成功检查只更新账户表的最新余额、状态和时间，不再新增成功历史。清空历史不影响账户的当前检查状态，后续出现的失败会正常记录。


## 存储管理与日志轮转

顶部“存储管理”入口可查询数据库及附属文件大小、数据库空闲页、余额采样数量、失败历史数量、其他数据文件占用，以及数据目录所在磁盘的可用空间与总容量。Docker Desktop 下显示的是容器可见的数据目录所在文件系统容量，不代表 Windows 各磁盘或整个 Docker 的占用。

默认启用每 24 小时自动清理，可在页面修改为 1～168 小时，支持关闭自动清理和立即清理。清理删除旧版本遗留的成功历史、31 天前的余额采样和过期登录会话，失败记录保留最新 20 条。不会删除站点、凭据、告警配置、管理员、有效登录会话或备份文件。设置和上次清理结果加密持久化，重启后继续按原计划执行；首次运行会执行一次清理。

立即清理可选择同时压缩 SQLite 数据库；自动清理在空闲页至少 1 MB 且占数据库文件至少 25% 时尝试压缩。压缩前检查可用磁盘空间；不足或压缩失败时，记录清理仍生效，空闲页可用于后续写入，页面会显示跳过原因。压缩期间数据库读写可能短暂等待。

Compose 使用 `json-file` 日志驱动，`max-size: "10m"`、`max-file: "3"`，限制当前服务容器的轮转日志约 30 MB。修改配置后需要重建容器才能应用，`docker compose up -d --build` 即可。应用不会访问 Docker socket，也不会清理其他容器、镜像、卷、宿主机日志或手动备份；其他数据文件仅统计不删除。

余额消耗根据相邻成功采样的余额下降估算，充值上涨不会抵扣已统计消耗；若充值和消费发生在两次检查之间，或者服务长时间中断，结果可能存在偏差。余额变化时立即记录采样，余额不变时每 5 分钟记录一次；采样从启用此功能后开始积累。预计可用时间按统计窗口内的平均消耗速度估算，检查失败时可能使用过期数据。
